# AdaptiveSec

## Adaptive Phishing Simulation & Security Training Platform

AdaptiveSec is a behavioral risk analysis and security awareness platform that moves beyond generic cybersecurity training. Instead of one-size-fits-all modules, it delivers controlled phishing simulations, tracks which psychological triggers each user falls for, and automatically assigns targeted training — while the context is still fresh.

## The Problem

Most cybersecurity training is generic and delivered long after real phishing attempts occur. Users forget the context and keep making the same mistakes. Organizations have no visibility into *which* users are most at risk or *why* — and they cannot provide interventions that address individual psychological vulnerabilities.

AdaptiveSec closes this gap.

---

## How It Works

1. **A simulated phishing link is surfaced to the user** — crafted around a psychological trigger (Urgency, Authority, Scarcity, or Social Proof).
2. **The user clicks the link** — the Chrome Extension captures the interaction silently and fires telemetry to the backend.
3. **The ML pipeline processes the event** — an XGBoost model scores the technical risk, and a CognitiveModel (Gemini 2.5 Flash → Ollama Llama 3.2 → keyword fallback) identifies the cognitive bias exploited.
4. **The user's vulnerability profile is updated** in Neo4j — repeated exposure to the same trigger increases that vulnerability's weight.
5. **A targeted training module is assigned** by the Recommendation Engine using Multi-Armed Bandit (Thompson Sampling) logic.
6. **A plain-English explanation is generated** by the ExplanationGenerator and pushed to the user in real time via WebSocket.
7. **Completing training reduces the user's risk score** and lowers their susceptibility to that trigger over time via adaptive click probability reduction.

## Getting Started

### Prerequisites

- Python 3.11+
- Node.js 18+
- Docker Desktop (for Redis + RabbitMQ)
- A `.env` file (see [Environment Variables](#environment-variables))

### 1. Start Infrastructure

Make sure Docker Desktop is running, then:

```bash
docker start rabbitmq
# If container doesn't exist yet:
docker run -d --name rabbitmq -p 5672:5672 -p 15672:15672 rabbitmq:management
```

### 2. Backend

```bash
cd backend
pip install -r requirements.txt
uvicorn main:app --reload
```

### 3. RabbitMQ Worker (separate terminal)

```bash
cd backend
python rabbitmq_worker.py
```

### 4. Seed Training Modules

Only needed on first run or after a full reset:

```bash
cd backend
python scripts/seed_training_modules.py
```

### 5. Frontend (dev mode)

```bash
cd frontend
npm install
npm run dev
```

Open `http://localhost:5173` — use the dev mode dropdown to log in as any synthetic agent.

### 6. Chrome Extension

```bash
cd frontend
npm run build -- --emptyOutDir
```

1. Open `chrome://extensions`
2. Enable **Developer Mode**
3. Click **Load unpacked** → select `extensionSetup/`
4. Sign in with Google OAuth

## Environment Variables

The `.env` file is never committed. Copy `.env.example` to `.env` and fill in your own keys:

```bash
cp .env.example .env
```

```env
NEO4J_URI=
NEO4J_USERNAME=
NEO4J_PASSWORD=
REDIS_URL=redis://localhost:6379
RABBITMQ_URL=amqp://localhost
JWT_SECRET=
GEMINI_API_KEY=
USE_OLLAMA=false
```

### Where to get your keys

| Variable | How to obtain |
| --- | --- |
| `NEO4J_URI` / `NEO4J_USERNAME` / `NEO4J_PASSWORD` | Create a free instance at [neo4j.com/cloud/aura](https://neo4j.com/cloud/aura) |
| `GEMINI_API_KEY` | Get a free key at [aistudio.google.com](https://aistudio.google.com) |
| `REDIS_URL` | Run locally: `docker run -d -p 6379:6379 redis` |
| `RABBITMQ_URL` | Run locally: `docker run -d --name rabbitmq -p 5672:5672 rabbitmq:management` |
| `JWT_SECRET` | Any random string — generate one: `python -c "import secrets; print(secrets.token_hex(32))"` |
| `USE_OLLAMA` | Set to `true` if you install [Ollama](https://ollama.com) locally with `ollama pull llama3.2:3b` |

To use Ollama as a local LLM fallback:

```bash
# Install from https://ollama.com
ollama pull llama3.2:3b
# Then set in .env:
USE_OLLAMA=true
```

## ML Pipeline

When a click event enters the RabbitMQ queue, it is processed sequentially:

1. **DataPreprocessor** — strips PII, hashes `user_id`, normalizes payload
2. **FeatureVectorBuilder** — 8-feature array: `url_length`, `num_subdomains`, `has_suspicious_keywords`, `contains_ip_address`, `is_https`, `time_of_day_encoded`, `session_fatigue_index`, `trigger_type_encoded`
3. **RiskScoringEngine** — XGBoost outputs `threat_score` (0–100) and `risk_delta` (+15 per click)
4. **CognitiveModel** — classifies psychological trigger: Urgency / Authority / Scarcity / Social Proof. Cascade: Gemini 2.5 Flash → Ollama Llama 3.2 3B → keyword fallback
5. **RecommendationEngine** — MAB Thompson Sampling assigns optimal training module; updates Neo4j graph
6. **ExplanationGenerator** — Gemini generates plain-English explanation, stores in Neo4j, publishes to Redis → WebSocket
